= Bundled codegen expert references

The files in `src/modules/codegen/documentations/` are a reviewed snapshot of domain-expert documentation.
They describe connector framework syntax; session uploads and scraped application documentation remain the source of target-specific facts.
`src/modules/codegen/selection/protocol_selectors.py` selects the relevant references and declarative sections for generation and repair.

== Deliberate adaptations

* Preserve the local REST / SCIM / SQL split. Shared SCIMREST schema and authentication pages stay at the documentation root; SQL has its own declarative reference.
* Expand the authentication include at snapshot time and omit SQL tutorial-navigation includes. The runtime reads plain text and does not resolve AsciiDoc includes or follow cross-references.
* Take the upstream plain-text topic references in the SCIMREST pages. SQL pages still use cross-references; rewrite them where the corresponding page is bundled under a different name.
* Keep the ConnId mapping introduction, built-in catalog, date-type guidance and low-code DSL section; omit generic SPI implementation and the gotchas section to control prompt size. UID omission from the final SPI schema must not suppress the native UID mapping.
* State in `connid-attributes.adoc` that the `ConnIdBuiltInAttribute.Mixin` constants (`UID`, `NAME`, `PASSWORD`, `ENABLE`, `ENABLE_DATE`, `DISABLE_DATE`, `LOCK_OUT`) need no import inside `connId { ... }` and that `CURRENT_PASSWORD` is not among them, and that an explicitly declared ConnId type outranks the detected type chain of `AttributeTypeResolutionRule`, including the forced built-in types (`DefinitionValue.moreSpecific`: `DECLARED` beats `DETECTED`).
* Add schema basics only to native-schema contexts, JSON type guidance to REST schemas, and complex-attribute/flattening guidance to SCIM schemas. Operation contexts retain section selection, including exclusion of the application-specific REST search example from generation. Claim "(chapter shown together with this page)" only for chapters every selecting context includes; JSON types are bundled for REST native schema only, and the ConnId reference keeps its bundled title.
* Keep `$` in the SCIM attribute-name grammar of `scim/complex-attributes.adoc` (`ScimPathFormat.ATTR_NAME`), and the hint in `rest/native-schema.adoc` that an array uses its item type with `multiValued`.
* Extract the documented `data` envelope in the REST search example (Groovy and YAML) and drop its undocumented `fields` query parameter.
* Repair the declarative search example in `declarative-yaml.adoc`: consistent sequence indentation (upstream mis-indents the `/users/{id}` entry, which does not parse), `//` comments inside Groovy blocks, only one empty-filter handler, and a neutral `fields` query parameter instead of the JIRA `jql` sample. Keep the search `method` description covering every `HttpMethod` value (parsed case-insensitively by `SearchEndpointsHandler`) and the non-contradictory `pagingSupport` sentence (`PagingSupportHandler` accepts either the mapping or the Groovy block).
* State in `declarative-yaml.adoc` that YAML write endpoints default to `POST` for every operation (`EndpointsHandler`), that only `{id}` is substituted, with the UID, on update and delete endpoints (`RestUpdateOperationBuilderImpl`, `RestDeleteOperationBuilderImpl`), and that `supportedAttributes` selector values are compared as strings (`SupportedAttributesHandler` passes the scalar text to `AttributeSupport`). Fix the YAML `apiKey` authentication example, which read the bearer token property.
* Correct `rest/create.adoc`: without `contentType` no body is sent, and an empty 2xx response takes the UID from the `Location` header or fails (`RestCreateOperationBuilderImpl`); the upstream text claims an unknown-UID success.
* Correct `rest/update.adoc`: the default body carries only the changed attributes, also for `PUT`, and the original state is read before every REST update (`requiresOriginalState` is always true). Use `{id}` in the activation and multi-endpoint examples, and replace the YAML activation example, whose Boolean `value` never matches, with a note.
* Correct the `implementation` context in `authentication.adoc`: `configuration`, `request` and `ctx` are properties of `AuthImplementationContext`, not methods, and `JwtAssertionBuilder.sign` takes a `GuardedString`, key bytes, or a secret with its Base64 flag.
* Retain SQL scripted-search restrictions from `sql/develop/declarative-yaml.adoc`. The SQL search interfaces lack the YAML bindings needed for scripted keys.

== Updating the snapshot

. Compare the mapped sources at the new source revisions, including included fragments and newly linked capability pages. Do not copy the source repositories wholesale into prompts.
. Resolve contradictions against the matching Java builders and YAML handlers, and record each local correction here. Keep target application examples illustrative.
. Audit every documented YAML key and closed value against its binding (`@Yaml.Key`, `@Yaml.Shortcut`, `@Yaml.ValueParser`, `@Yaml.Custom`, `@Yaml.Map`, `@Yaml.Sub`, or a `@Script.Runtime` closure) and against `YamlSchemaLoader`; a documented key without a binding is rejected at connector load.
. Update prompt rules and `src/modules/codegen/connector_yaml_schema.py` together when supported syntax changes; retain Groovy syntax validation for string hooks and literal validation for mapping alternatives.
. Run `uv run poe test test/unit/modules/codegen test/integration/modules/codegen -q`, `uv run poe lint`, `uv run poe typecheck`, and `uv run poe importcheck`. The tests cover prompt rendering, bundled declarative examples, supported and rejected syntax, and the HTTP envelope.
. Update the revisions and mapping above. Document connector runtime compatibility in `docs/milestone-notes.adoc` when new output syntax requires a newer framework.

The refresh does not require recreating the development database or changing backend environment variables. Existing artifacts are not rewritten automatically.
