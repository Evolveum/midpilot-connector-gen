= Digester
:toc: left

link:index.adoc[← Pipeline overview] | link:../index.adoc[Documentation index]

The digester turns the documentation chunks stored in the session into a
structured model of the target API: metadata, authentication, object classes,
endpoints, attributes and relations. Everything the
link:codegen.adoc[codegen] stage generates is built on these outputs.

Module: `src/modules/digester/`

== Endpoints

All paths are prefixed with `/api/digester`. Each resource follows the
link:../sessions-and-jobs.adoc[job pattern]: `POST` enqueues extraction,
`GET` polls status/result, `PUT` overwrites the stored result manually.

[cols="2,3", options="header"]
|===
| Resource | Purpose

| `/{sessionId}/metadata`
| Application/API metadata — most importantly the detected
  link:../api-type.adoc[`apiType`] and base API URL. *Run this first.*

| `/{sessionId}/auth`
| Supported authentication methods (API key, OAuth2, basic, …).

| `/{sessionId}/classes`
| Object classes (User, Group, …) with confidence ranking
  (high/medium/low). Accepts an `apiType` query override.

| `/{sessionId}/classes/{objectClass}/endpoints`
| CRUD/search endpoints for one object class.

| `/{sessionId}/classes/{objectClass}/attributes`
| Attribute schema for one object class.

| `/{sessionId}/relations`
| Relations between object classes (e.g. user–group membership).

| `/{sessionId}/connectivity-endpoint`
| A cheap endpoint suitable for a connection test.
|===

== How extraction works

1. *Chunk selection* — `selection/` picks the relevant subset of the
   session's documentation chunks per extraction type (criteria over chunk
   categories, `common/chunk_filter`), so the LLM never sees the whole corpus.
2. *Protocol-specific extractors* — the worker layer under `extractors/` is
   split by protocol: `rest/`, `scim/`, `sql/`, chosen by the effective
   link:../api-type.adoc[apiType]. SCIM uses a fixed baseline bundle
   (`extractors/scim/baseline.py`) of standard SCIM contracts instead of
   re-deriving everything from the documentation.
3. *Sequence-based extraction* — for large extractions (attributes, auth) the
   LLM returns start/end *markers* into the source text; the actual content is
   then located by fuzzy matching in a process pool (`src/pool.py`) rather
   than being re-generated by the LLM. Tolerances are configurable
   (`fuzzy_*_marker_error_ratio`, `sequence_max_length`).
4. *Aggregation* — per-chunk results are merged, deduplicated, and
   confidence-ranked across documents (`aggregation/`). Low-evidence metadata
   values are dropped (`info_metadata_uncertainty_threshold`).

Progress of the multi-phase jobs is reported through `JobStage` values
(discovery, deduplication, building, sorting, …).

== Order matters

IMPORTANT: Run `metadata` before anything else. It detects and stores the
link:../api-type.adoc[apiType]; object classes, endpoints, attributes and all
codegen steps resolve their protocol from it. Without it the service falls
back to REST, which produces garbage for SCIM or SQL targets.

The intended order within the digester:
`metadata` → `auth` → `classes` → per class `endpoints` → per class
`attributes` → `relations` / `connectivity-endpoint`. Endpoints and
attributes require object classes to exist (jobs fail with
`ObjectClassesNotFoundError` otherwise); relations build on extracted
classes/attributes.

== Pitfalls

IMPORTANT: A wrong or missing `apiType` is the most common cause of bad
digester output — see link:../api-type.adoc[API type] for detection details
and the per-request `apiType` query override.

NOTE: Results are cached by input for `+DIGESTER__DIGESTER_INPUT_CHECK_INTERVAL+`
(default 4 weeks); use `skipCache=true` when re-running after prompt or
documentation changes.

NOTE: Auth extraction switches to extended selection criteria when the session
has fewer than `+DIGESTER__AUTH_MIN_DOCUMENTATION_ITEMS+` (default 15)
documentation items — tiny documentation sets behave differently by design.

NOTE: Any result can be corrected manually via `PUT` before moving on —
fixing an object class list by hand is often cheaper than tuning the
extraction.

== Related settings

`+DIGESTER__*+` — concurrency, retries, apiType-detection signals, fuzzy
matching tolerances, sequence length bounds. See
link:../configuration.adoc[Configuration] and `src/config/digester.py` for
the full list.
