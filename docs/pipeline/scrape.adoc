= Scrape
:toc: left

link:index.adoc[← Pipeline overview] | link:../index.adoc[Documentation index]

Scrape crawls documentation pages starting from a set of URLs, follows
relevant links, and converts the content into processed documentation chunks
stored in the session — the input for the link:digester.adoc[digester].

Module: `src/modules/scrape/` (crawling built on crawl4ai + Playwright via
`src/integrations/web/`).

== Endpoints

[cols="2,3", options="header"]
|===
| Endpoint | Purpose

| `POST /api/scrape/{sessionId}/scrape`
| Enqueue a scrape job. Body: `ScrapeRequest` — `starterLinks` (required),
  `applicationName` (required), `applicationVersion`, `skipCache`.

| `GET /api/scrape/{sessionId}/scrape`
| Poll the job status; progress is reported per scraper iteration.
|===

== Process

1. *Crawl* the starter links (typically the link:discovery.adoc[discovery]
   output). A URL served as JSON, YAML or plain text is downloaded as a data
   file (up to `+SCRAPE_AND_PROCESS__MAX_DATA_DOCUMENTATION_BYTES+`); any other
   page is rendered with crawl4ai/Playwright.
2. *Keep only documentation.*
   * A rendered page is saved as the markdown of its main content: the first of
     `+SCRAPE_AND_PROCESS__MAIN_CONTENT_SELECTORS+` (`article`, `main`,
     `[role=main]`) that matches one element holding most of the page text,
     otherwise the page body without header, footer and sidebars. Navigation is
     removed; tables and code samples are kept. A page without main content is
     not saved, but its links are still followed.
   * A data file is saved when it is an API description (OpenAPI 3, Swagger 2,
     SCIM schemas or resource types, JSON Schema) or plain text such as a raw
     markdown file. Other JSON/YAML (`package.json`, translation bundles) is
     saved only when it is a starter link.
3. *Fetch referenced specifications.* A page built from an API description
   (Swagger UI including `swagger-initializer.js` and `configUrl`, Redoc,
   Stoplight Elements, RapiDoc, Scalar), a `<link rel="alternate">` or a
   JSON/YAML download link to one, or a link whose URL names one
   (`openapi.json`, `swagger.yaml`, `/v3/api-docs`) leads to the document
   itself, fetched in the same iteration and never crawled further. GitHub file
   pages are read as raw files. Only URLs on the trusted domains and raw GitHub
   files are fetched, at most `+SCRAPE_AND_PROCESS__MAX_SPEC_URLS_PER_PAGE+` per
   page, and only a recognized API description is saved.
4. *Collect links* found on the scraped pages; normalize them (relative →
   absolute, strip anchors/trailing slashes) and drop URLs whose path segment
   matches a configured forbidden part (login, pricing, changelogs, non-English
   locales, …).
5. *Filter* the remaining links with an LLM to keep only
   documentation-relevant ones, then feed them into the next iteration of the
   scraper loop. The loop runs up to
   `+SCRAPE_AND_PROCESS__MAX_SCRAPER_ITERATIONS+` (default 4) iterations. Links
   found on the last iteration are never scraped, so they are not sent to the
   LLM; they only decide between the finish reasons `max-iterations-reached`
   (in-scope links remain) and `no-more-links`.
   Robots.txt denials and permanent 4xx responses are not retried; 408, 425,
   429 and server errors are.
6. As each document is saved, it is *chunked* (token-based,
   `+SCRAPE_AND_PROCESS__CHUNK_LENGTH+` tokens per chunk) and each chunk is
   *processed by an LLM* (`src/documents/processing/`): cleaned up,
   categorized (`spec_json`, `reference_api`, `tutorial`, …) and annotated
   with metadata, including `retrieval` (starter link, recognized
   specification and its canonical hash, see
   link:../sessions-and-jobs.adoc#chunk-metadata[chunk metadata]).
   Preserved SQL/SCIM schemas that exceed the single-schema budget are split
   into structurally valid sub-schemas instead of naive cuts. Conndev uploads
   are the exception: their binding is classified deterministically and the
   chunk-processing LLM is skipped.
7. Processed chunks are persisted as `documentation_chunks` rows with
   `source='scraper'`.

Uploaded files (see link:../sessions-and-jobs.adoc[Sessions and jobs]) go
through steps 6–7 of the same machinery with `source='upload'`.

== Pitfalls

NOTE: Scraping is the slowest and most fragile stage: it depends on the target
site's structure, anti-bot measures, and the LLM link filtering. If you
already have good documentation (an OpenAPI spec, an exported doc bundle),
uploading it directly to the session is faster and more reliable than
scraping.

NOTE: `applicationName` and `applicationVersion` are passed to the chunk
processing and link selection prompts. The digester does not filter chunks by
version.

NOTE: When a site keeps its content outside `article`/`main`, add its
container to `+SCRAPE_AND_PROCESS__MAIN_CONTENT_SELECTORS+` (CSS selectors,
validated at startup). Without a match the page body is used, which still
excludes header, footer and sidebars.

WARNING: The forbidden-URL list (`+SCRAPE_AND_PROCESS__FORBIDDEN_URL_PARTS+`)
filters out many locale prefixes (`de`, `fr`, `es`, …). An entry matches a whole
URL path segment or file name (`/de/` or `/docs/de`, not `/developer`). If the
documentation you need lives under such a path, adjust the setting.

== Related settings

`+SCRAPE_AND_PROCESS__*+` — scraper loop bounds, main-content selectors, data
file and referenced-spec limits, chunking, concurrency, retry behavior, chunk
categories. See link:../configuration.adoc[Configuration] and
`src/config/scrape.py` for the full list.
