= Configuration
:toc: left

link:index.adoc[← Documentation index]

The service is configured exclusively through environment variables (or a
`.env` file in the project root — see `.env-example`). Settings are Pydantic
models in `src/config/`, grouped by domain and nested with the `+__+`
delimiter:

----
LOGGING__LEVEL=error
DATABASE__HOST=localhost
DIGESTER__MAX_CONCURRENT_LLM_CALLS=10
----

The code in `src/config/*.py` is the source of truth for every option and its
default — this page only maps the groups and highlights the settings you are
most likely to touch.

== Settings groups

[cols="1,1,3", options="header"]
|===
| Prefix | File | Scope

| `+APP__+` | `src/config/app.py`
| Server: host/port (default `8090`), workers, API base path (`/api`),
  timeouts, optional TLS (`ssl_certfile`/`ssl_keyfile`).

| `+JOBS__+` | `src/config/jobs.py`
| Durable PostgreSQL worker: enable/disable consumption, concurrent jobs per
  process, queue polling, claim/heartbeat timing, crash attempts, graceful
  shutdown, and the per-process CPU helper-pool size.

| `+LOGGING__+` | `src/config/logging.py`
| Log level and formatting.

| `+DATABASE__+` | `src/config/database.py`
| PostgreSQL connection (`URL`, host/ports/user/password/name, pool size).

| `+LLM__+` | `src/config/llm.py`
| LLM client: any OpenAI-compatible API (`OPENAI_API_BASE`, default
  OpenRouter), `MODEL_NAME`, `OPENAI_API_KEY`, provider preference order,
  optional `REASONING_EFFORT`, request timeout, connection pool, transient
  retry policy. *Shared by all modules* — there is no per-module model
  selection.

| `+LANGFUSE__+` | `src/config/langfuse.py`
| Tracing: `TRACING_ENABLED` (default off), project keys, environment name.

| `+SEARCH__+`, `+BRAVE__+` | `src/config/search.py`
| Discovery input-cache window; Brave Search API key/endpoint (without a key
  the ddgs backend is used).

| `+SCRAPE_AND_PROCESS__+` | `src/config/scrape.py`
| Scraper loop bounds (`MAX_SCRAPER_ITERATIONS`, `MAX_LINKS_PER_DOCUMENTATION`,
  `FORBIDDEN_URL_PARTS`), chunking (`CHUNK_LENGTH`,
  `SINGLE_ITEM_SCHEMA_MAX_TOKENS`), chunk-processing concurrency and retries,
  chunk categories, version heuristics, scrape input-cache window.

| `+DIGESTER__+` | `src/config/digester.py`
| Extraction concurrency and retries, digester input-cache window,
  link:api-type.adoc[apiType] detection signals (scim.cloud, LLM knowledge,
  web search — enable flags, thresholds, query templates), fuzzy
  sequence-matching tolerances, auth criteria threshold, debug logging.
|===

NOTE: The external apiType signal settings cover REST and SCIM. SQL is selected
from uploaded documentation by the per-chunk documentation signal, or declared
manually in session metadata; there is no SQL registry/knowledge/web-search
toggle.

== Settings you will most likely change

[cols="2,1,2", options="header"]
|===
| Variable | Default | Why change it

| `+LLM__OPENAI_API_KEY+` | — | Required for any LLM call.
| `+LLM__OPENAI_API_BASE+` | OpenRouter | Point to a different
  OpenAI-compatible provider.
| `+LLM__MODEL_NAME+` | `openai/gpt-oss-120b` | Model selection (cost/quality).
| `+DATABASE__URL+` | — | Required; asyncpg connection string.
| `+APP__WORKERS+` | `1` | HTTP and job-consumer processes in this container.
  Every process claims independently from the same PostgreSQL queue.
| `+JOBS__ENABLED+` | `true` | Run an embedded queue consumer in this FastAPI
  process. Disable it for API-only pods; the queue is then drained by processes
  started with `python -m src.jobs.runtime`, which ignore this setting. Note
  that a process with it disabled still accepts requests that create jobs -
  they simply stay `queued` until some consumer exists.
| `+JOBS__MAX_CONCURRENT_JOBS+` | `2` | Maximum running jobs in each process.
  This is separate from the LLM semaphore because one job can fan out into
  several LLM calls.
| `+JOBS__POLL_INTERVAL_SECONDS+` | `0.5` | Delay between empty queue polls in
  each process.
| `+JOBS__REAPER_INTERVAL_SECONDS+` | `30` | Interval for expired/invalid job
  repair sweeps. Reaping is not performed on every claim.
| `+JOBS__CLAIM_TIMEOUT_SECONDS+` | `300` | Time after the last successful
  heartbeat before another worker may reclaim an interrupted job.
| `+JOBS__HEARTBEAT_INTERVAL_SECONDS+` | `30` | Interval between claim
  refreshes. It must be lower than the claim timeout.
| `+JOBS__MAX_ATTEMPTS+` | `3` | Maximum crash/reclaim executions before an
  expired job is failed.
| `+JOBS__SHUTDOWN_GRACE_SECONDS+` | `10` | Time allowed for running jobs to
  finish before shutdown cancels and returns their claims to the queue.
| `+JOBS__DOCUMENTATION_WRITE_BATCH_SIZE+` | `20` | Maximum documentation
  writes in one transaction during scrape/cache persistence.
| `+JOBS__CPU_PROCESSES+` | `1` | CPU helper processes created by each enabled
  job worker. Keep this small when `APP__WORKERS` or pod replicas are increased.
| `+BRAVE__API_KEY+` | empty | Better discovery/web-search results than the
  ddgs fallback.
| `+LANGFUSE__TRACING_ENABLED+` | `false` | Turn on request/LLM tracing during
  development.
| `+DIGESTER__APITYPE_SCIM_WEB_SEARCH_ENABLED+` +
  `+DIGESTER__APITYPE_REST_WEB_SEARCH_ENABLED+` | `true` | Each metadata
  extraction performs external web searches (and fetches result pages);
  disable to cut latency/cost when documentation alone is sufficient.
| `+*__*_INPUT_CHECK_INTERVAL+` | 4 weeks | Result-cache windows for
  discovery/scrape/digester (see
  link:sessions-and-jobs.adoc[Result caching]).
|===

NOTE: Defaults aim to be production-appropriate. Prefer adding a new explicit
setting over hardcoding environment-specific values — every tunable above is
defined once in `src/config/` and injected where needed.

IMPORTANT: `+DIGESTER__MAX_CONCURRENT_LLM_CALLS+` remains process-local. For
example, four application workers with the default value `10` can issue up to
40 concurrent digester LLM calls. A cluster-wide LLM budget is intentionally
not part of the durable-job change.

Database pools are also created per process. The deployment's possible
connection count is approximately
`processes × (DATABASE__POOL_SIZE + DATABASE__MAX_OVERFLOW)`; size PostgreSQL
and these settings together.
