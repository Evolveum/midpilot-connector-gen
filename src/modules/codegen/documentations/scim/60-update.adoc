= SCIM Update operation customization
:page-nav-title: Update operations
:page-upkeep-status: orange
:page-toc: top

This document is part of the SCIM 2.0 connector tutorial. See xref:index#[Index] for other topics.

SCIM 2.0 update operations use either PUT (full replacement) or PATCH (partial update) HTTP methods.

IMPORTANT: The built-in SCIM update handler issues a *full PUT* only. SCIM `PATCH` is **not
implemented yet** - no PATCH request is ever sent by the built-in handler, and the `put { }` /
`patch { }` customization blocks documented below are *not functional yet* (in development). Do
not rely on them, and do not generate a `patch { }` block as if it worked. For a working custom
update today, generate a REST-style update endpoint instead: `update { endpoint(PUT, "/Users/{id}")
{ ... } }` or `update { endpoint(PATCH, "/Users/{id}") { ... } }` (see the REST update reference),
or the declarative `update.endpoints[]` YAML equivalent from <declarative_docs>.

The built-in full-PUT update itself (no customization) does work with no script needed for a
well-behaved SCIM 2.0 server.

== PUT vs PATCH

|===
|Operation |HTTP Method |SCIM Mode |When to use
|PUT |PUT |Absolute |Replace entire resource
|PATCH |PATCH |Relative |Modify specific attributes
|===

== PUT (Absolute mode)

Full resource replacement - sends all updateable attributes:

[source,groovy]
----
objectClass("User") {
    update {
        scim {
            put {
                supportedAttributes "displayName", "nickName", "title"
            }
        }
    }
}
----

The framework sends all `updateable` attributes in the request body.

== PATCH (Relative mode)

Partial update - sends only changed attributes. SCIM PATCH uses operation-based format:

[source,groovy]
----
// Preview only - not functional yet (see the IMPORTANT note above)
objectClass("User") {
    update {
        scim {
            patch {
                supportedAttributes "externalId", "displayName", "nickName", "profileUrl"

                supportedAttribute("userName") {
                    limitations {
                        operations ADD, REPLACE
                        maxPerRequest 1
                    }
                }

                supportedAttribute("active") {
                    limitations {
                        operations ADD, REPLACE
                        maxPerRequest 1
                    }
                }
            }
        }
    }
}
----

== Patch operations

SCIM PATCH supports operations:

* `ADD` - Add value(s) to multi-valued attribute
* `REPLACE` - Replace attribute value(s)
* `REMOVE` - Remove value(s) from multi-valued attribute

== Attribute limitations

Configure SCIM-specific limitations:

[source,groovy]
----
patch {
    supportedAttribute("userName") {
        limitations {
            operations ADD, REPLACE
            maxPerRequest 1
        }
    }
}
----

Limitations:

* `operations` - Which PATCH operations are allowed (ADD, REPLACE, REMOVE)
* `maxPerRequest` - Maximum operations of this attribute per request

== Complete PATCH example (AWS style)

[source,groovy]
----
// Preview only - not functional yet (see the IMPORTANT note above)
objectClass("User") {
    update {
        scim {
            patch {
                supportedAttributes "externalId", "displayName", "nickName", "profileUrl",
                    "title", "userType", "preferredLanguage", "locale", "timezone", "name",
                    "enterprise", "emails", "addresses", "phoneNumbers"

                supportedAttribute("userName") {
                    limitations {
                        operations ADD, REPLACE
                        maxPerRequest 1
                    }
                }

                supportedAttribute("active") {
                    limitations {
                        operations ADD, REPLACE
                        maxPerRequest 1
                    }
                }

                supportedAttribute("groups") {
                    limitations {
                        operations ADD, REMOVE, REPLACE
                        maxPerRequest 100
                    }
                }
            }

            put {
                // PUT endpoint for full replacement
            }
        }
    }
}
----
