= SCIM Schema customization
:page-nav-title: Schema customization
:page-upkeep-status: orange

While the framework provides automatic schema discovery, you often need to customize it for your specific use case.

== Schema customization blocks

Schema customization is defined in Groovy scripts using the `objectClass()` and `attribute()` builders with SCIM-specific blocks.

The first argument of `attribute()` is the *native connector attribute name* - the name the application's own
documentation uses. The `scim { path ... }` block carries the SCIM wire path. The two are often identical, but when
the application documents a different name, the native name wins and the wire path stays inside the `scim` block.

[source,groovy]
----
objectClass("User") {
    scim {
        extension("enterprise", "urn:ietf:params:scim:schemas:extension:enterprise:2.0:User")
    }

    attribute("givenName") {
        scim {
            path attribute("name").child("givenName")
        }
    }

    // Native name and SCIM wire attribute differ: the application documents the field as "Username",
    // while the SCIM API exposes it as "userName".
    attribute("Username") {
        scim {
            path attribute("userName")
        }
    }
}
----

== SCIM extensions

Define SCIM schema extensions using the `scim { extension(...) }` block:

[source,groovy]
----
objectClass("User") {
    scim {
        extension("enterprise", "urn:ietf:params:scim:schemas:extension:enterprise:2.0:User")
    }
}
----

Extensions allow you to reference attributes from SCIM schema extensions.

== Path-based attribute mapping

SCIM uses nested attribute paths (e.g., `name.givenName`). Map these to flat ConnId attributes:

[source,groovy]
----
objectClass("User") {
    attribute("givenName") {
        scim {
            path attribute("name").child("givenName")
        }
    }

    attribute("familyName") {
        scim {
            path attribute("name").child("familyName")
        }
    }

    attribute("employeeNumber") {
        scim {
            path extension("enterprise").child("employeeNumber")
        }
    }
}
----

The `path` method specifies the SCIM attribute path. Use `attribute()` for regular attributes and `extension()` for extension attributes.

== Value filter for multi-valued attributes

For multi-valued attributes with primary/primary flags, use value filters:

[source,groovy]
----
attribute("primaryEmail") {
    scim {
        path attribute("emails").valueFilter("primary", true).child("value")
    }
}
----

This maps the `value` field from the email object where `primary` is `true`.

== ConnId attribute mapping

Map native connector attributes to ConnId built-in attributes:

[source,groovy]
----
objectClass("User") {
    connIdAttribute("UID", "id")
    connIdAttribute("NAME", "Username")
}
----

The ConnId framework requires `UID` and `NAME` attributes. The second argument is the *native connector attribute
name*, never the SCIM wire attribute. In the example above the application documents the login field as `Username`
and the SCIM API exposes it as `userName`, so the ConnId mapping uses `Username` and the wire name appears only in
that attribute's `scim { path ... }` block.

The same mapping may also appear in the ConnId mapping script for this object class. Both scripts are merged into
one connector, so the native name must be identical in both; a mismatch is rejected.

== SCIM-specific schema blocks

The `scim` block supports:

|===
|Block |Description |Example
|`extension(name, uri)` |Define SCIM schema extension |`extension("enterprise", "urn:...")`
|`path(path)` |Specify SCIM attribute path |`path attribute("name").child("familyName")`
|`name(name)` |Override SCIM attribute name |`name "displayName"`
|`onlyExplicitlyListed()` |Only include explicitly listed attributes |`onlyExplicitlyListed()`
|===

== Complete example

[source,groovy,highlight=9,20,23,26,29,32]
----
objectClass("User") {
    scim {
        extension("enterprise", "urn:ietf:params:scim:schemas:extension:enterprise:2.0:User")
    }

    connIdAttribute("UID", "id")
    connIdAttribute("NAME", "Username")

    attribute("Username") {
        scim {
            path attribute("userName")
        }
    }

    attribute("givenName") {
        scim {
            path attribute("name").child("givenName")
        }
    }

    attribute("familyName") {
        scim {
            path attribute("name").child("familyName")
        }
    }

    attribute("employeeNumber") {
        scim {
            path extension("enterprise").child("employeeNumber")
        }
    }

    attribute("primaryEmail") {
        scim {
            path attribute("emails").valueFilter("primary", true).child("value")
        }
    }
}
----
