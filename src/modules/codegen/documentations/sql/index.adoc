= Develop SQL database connector

This reference covers database connector generation from an uploaded SQL schema, either a midPoint
conndev SQL export or a raw `CREATE TABLE` / JSON schema.

The uploaded schema provides tables, columns and - for a raw schema - primary keys, foreign keys,
nullable flags and generated columns. A conndev export instead provides authoritative ConnId types
and `required` / `creatable` / `updateable` flags, but no keys and no nullability.

== Principles

* There are no endpoints to call and no table listing to extract. Each attribute carries the
  `table` and `column` it maps to.
* The table and column mapping is declared once by the native schema. Operations only declare
  capabilities inside a native `sql {}` block; they never carry statements or table names.
* Identity comes from the primary key. Where the primary key is unknown, leave a TODO instead of
  guessing it from a column name.
* Use foreign keys only when joins or relationship handling are required by the selected object
  class.
* Do not write generated, identity or serial columns during create.
* Do not update primary keys or generated columns.
* Leave TODO comments for missing join, cascade or transaction semantics instead of guessing.

== Operation block shape

Every operation follows the same shape - the operation block holds a `sql { builtIn { ... } }`
declaration and nothing REST-like:

[source,groovy]
----
objectClass("m_user") {
    search {
        sql {
            builtIn {
                enabled true
                emptyFilterSupported true
                anyFilterSupported true
            }
        }
    }

    create {
        sql {
            builtIn {
                enabled true
            }
        }
    }

    update {
        sql {
            builtIn {
                enabled true
            }
        }
    }

    delete {
        sql {
            builtIn {
                enabled true
            }
        }
    }
}
----

`builtIn` accepts only `enabled`, `emptyFilterSupported` and `anyFilterSupported`; the last two are
meaningful for search. `attributeResolver` and `custom` blocks keep the same shape as in the REST
and SCIM connectors and are generated only when the built-in behavior is provably insufficient.

See xref:40-search.adoc[Search], xref:50-create.adoc[Create], xref:60-update.adoc[Update] and
xref:70-delete.adoc[Delete] for the per-operation rules.
