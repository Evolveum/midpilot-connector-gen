= SQL update operation

The database connector builds the update itself from the native schema mapping and identifies the
row by the primary key. The `update` block only declares that the built-in update is used for this
object class.

== Built-in update

[source,groovy]
----
objectClass("m_user") {
    update {
        sql {
            builtIn {
                enabled true
            }
        }
    }
}
----

`enabled` is the only key `builtIn` needs for update. Do not write statements, predicates or value
bindings into the operation block.

== Which columns are written

The framework writes only the changed attributes that are marked `updatable` in the extracted
schema. That flag already accounts for the cases below:

* Primary key columns are not updated.
* Generated columns are not updated.
* A conndev export marks a column non-updatable explicitly; a raw schema derives it from the
  primary key.

== Rules

* Never render a table name as `endpoint(...)`, a path, or a hand-written `UPDATE` statement.
* Never generate REST or SCIM constructs.
* A conndev SQL export carries no primary keys. When no attribute is marked `primaryKey`, leave a
  TODO instead of guessing the identity column from a column name.
* When the attributes of the object class span several tables and the update order is not
  documented, leave a TODO instead of guessing it.
